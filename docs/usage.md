# Using Unscene

## Theme integration
Unscene delegates ordinary button surfaces, icon placement, borders, hover and press states to the active Qt/OBS style. Each expanded scene forms a continuous rounded card: a stronger header with square lower joins, contiguous source bands and rounded bottom corners. Collapsed headers keep all four rounded corners. Scene headers, branch containers and selected/hovered rows use metric-derived rounded geometry; row controls retain native sizing but use the owning scene surface for icon ink, transparent resting backgrounds and rounded hover/press state layers. The live indicator alone retains a filled tonal circle. Button dimensions use native style content sizing and icon metrics; row and dock spacing are compact while explicit theme minimum heights are preserved. Left padding uses a 1px dock margin, at most 4px base row inset, and 6–8px per hierarchy level; native artwork and controls retain their sizes. Layout spacing uses Qt metrics and the toolbar is a native QToolBar. Source artwork uses native OBS theme icon properties when available. Row controls follow their scene surface; native selection colors remain authoritative. Theme changes rebuild the presentation without changing source state. Thumbnail density, semantic action glyphs, custom row accents, hierarchy indentation and animation timing remain Unscene design choices; not every private OBS theme token is exposed through Qt.

## Navigation and density
Search the selected tab (or optionally all tabs) by name, including sources inside collapsed scenes and groups. Matching branches retain their hierarchy; clearing search restores the previous expansion state. Expand/collapse settings persist per collection name using scene and item identities. Under Dock settings, Scene thumbnails and Source thumbnails independently offer Compact (icons), Standard, or Large. Compact disables automatic snapshot capture for those rows while retaining custom artwork.

## Scene tabs and folders
Top-level organizational folders appear as tabs; existing folder data and scene UUID memberships are reused without migration. **Unfiled** shows scenes with no folder membership. Tabs are views of the same loaded OBS scene collection, not collection switches: changing tabs never activates a scene or changes the program/preview output. The broadcast icon marks the tab containing the program scene; tab tooltips also identify the preview tab. Tabs use native scroll buttons when space runs out, and the down-arrow menu lists every tab. Click + to create a tab. Dock settings → Hide tab row when only one tab is enabled by default and persists across restarts. The entire strip is hidden when Unfiled is the only tab; creating another tab immediately restores it. New scene tab and All scene tabs / pinned scenes remain available in Dock settings when the strip is hidden. Disable the option to keep the strip visible at all times. Right-click a tab for rename, appearance, new subfolder, move, duplicate folder structure (without copying scenes), or remove while preserving contents. Nested folders remain expandable rows. Scene More actions → Move to tab / folder assigns scenes to a tab or nested folder, or returns them to Unfiled. Removing a tab promotes child folders to tabs and moves its direct scenes to Unfiled; it never removes OBS scenes or sources. The selected tab and expansion state persist separately for each actual OBS collection name. Search defaults to the selected tab; enable Search all tabs in Dock settings to search the whole collection, including collapsed branches. Clear the query to return to the selected tab. Expand-all and collapse-all operate within the selected tab. Folder organization does not change OBS scene order, activation, or composition. Drag tabs left or right to change their display order (Unfiled stays first). Drag a scene or nested folder onto a different tab or an eligible folder row to move it; the target is outlined. Dragging a nested folder onto Unfiled promotes it to its own tab. Tab right-click also offers Move tab left/right. Organization undo/redo is available in Dock settings and folder/tab menus; it restores up to 64 changes in the current collection session, independently of OBS edit history. Tab selection and expansion are navigation preferences, not history entries. Source drag remains same-parent only. Drag scenes above or below siblings, or use Move scene up/down in their menu, to persist a presentation-only order independent of OBS native scene order. Pinned scenes precede other scenes in the same folder and are reordered within their own tier. Search disables row dragging. Folder organization does not travel with a separately exported scene collection, and collection renames do not migrate preferences.

Tab labels show total descendant scene counts. Tab Appearance provides custom artwork and a color accent dot. Pin scene in a scene’s More actions menu adds a persistent favorite; the tab overflow’s Pinned scenes menu jumps to the scene without activating it. Pinning is a navigation preference, not an organization undo entry. New scene here in tab/folder menus or New scene in this tab in Dock settings creates a real OBS scene without activating it. Duplicate scene (shared sources) creates a new scene with its own item instances and existing source references; source properties and filters remain shared. Creation and duplication are not native undo actions; organization undo can move their membership, but cannot delete the newly created OBS scene.

Scene and folder titles use a semibold theme-derived font at 115% of the base size, source names normal weight, tabs medium weight, and status text 90% of the theme font size. Both point-size and pixel-size theme fonts are supported.

## Second-row shortcuts and transitions
The live/activate scene control occupies the far-right position, after Add source and More actions. Click anywhere on a scene header (title, artwork, status, padding or empty shortcut-row space) or its disclosure arrow to expand/collapse the source list and transition shortcuts together. Action buttons remain independent, and expanding a card never activates the scene. During search, matching branches remain expanded. Expanded scene headers also expose Filters and Projector shortcuts. Click a source title for its shortcuts. Visual sources have a Projector icon alongside their hover actions. Video sources expose Transform (opens the inspector at Transform), In, Out, and Blending mode/method, plus the existing item actions. Source In/Out use OBS native show/hide transitions on the exact scene item, not on every occurrence of a source. Choose a transition type and duration, or None; configurable transition properties are available in More actions. Transition type/duration edits support native OBS undo/redo with item and expected-state checks; editing detailed transition properties is separate.

Top-level scene In sets OBS's native destination override using an existing configured scene transition. Scene Out is a separate Unscene rule used only when activating another scene through Unscene in normal mode, and only if that destination has no incoming override. The destination's native setting is restored after the activation. Studio Mode preview selection and native OBS transitions/hotkeys are unchanged. This is not a global independent outgoing transition API. Scene override edits do not currently register native undo actions.

## Graphics isolation
Dock settings → Snapshot capture defaults to Cached artwork only (no GPU capture). Existing session snapshots and custom artwork remain visible; on a fresh session, uncached rows use icons. The in-memory snapshot cache evicts least-recently-used entries at its 512-entry limit and clears when switching collections. Opt in to Generate snapshots when outputs are idle to populate thumbnails. Capture is blocked while OBS reports streaming, recording, replay buffer or virtual camera active. Refresh does not discard cached snapshots while capture is blocked. Snapshot capture in the optional idle mode still uses synchronous graphics-context access; it is not a zero-contention path. Animation uses only GUI-side widget transitions.

## Motion
Unscene uses short, interruptible Qt transitions for scene/group expansion, scene/source secondary controls, search results, hover buttons, disclosure chevrons and snapshot refresh feedback. Unchanged rows are retained instead of recreated. Dock settings → Animations offers Off, Fast (90 ms) and Smooth (150 ms, default), persisted independently of the scene collection. Large structural changes skip row animation; snapshot capture waits until layout transitions settle. Motion is limited to Unscene's own widgets, not native OBS menus or dialogs.

## Inspector
Select a source and click Transform (Inspector for non-visual sources) (or More actions → Open inspector). The resizable bottom panel edits the exact scene item, including items in inactive scenes. Pin retains the target while navigating; otherwise it follows clicked visual sources when there is no unapplied draft. Apply commits position, scale, rotation, alignment, bounds and crop in one OBS undoable action; Discard reloads current values. Locked items cannot be edited. Concurrent changes are detected on Apply rather than overwritten. Transform presets persist across restarts; load into the draft, then Apply. Save can replace an existing preset; Delete removes it. Numeric presets are absolute, not normalized to source dimensions. The Transform tab is available for visual sources; audio-only sources can use the Filters and Usage tabs. The Filters tab lists the actual shared filter stack, supports compatible filter creation, enable/disable, same-category reordering, renaming and confirmed removal. Edit opens the native Filters dialog for detailed settings. Filter mutations are shared across every instance of the source. Add, remove, enable/disable, reorder and rename register native OBS undo/redo actions without switching the editing scene. Removed filters are restored from saved OBS source data, including identity, settings and stack position. Undo targets the original collection and source UUID, and skips missing or conflicting targets rather than altering another source. The Usage tab counts direct instances by scene/group, including collapsed branches, and updates on entry or Refresh usage; it does not count indirect nested-scene references. Source Properties still opens the native dialog.

Inspired by [Source Inspector Dock](https://github.com/prgmitchell/source-inspector-dock); the inspector implementation is independently authored using public OBS APIs.

## Portable filters
In the Inspector's Filters tab, the three-dot **More filter actions** menu copies one filter or an entire stack to the system clipboard, or exports/imports JSON. Single-filter transfers use native OBS saved-source JSON (the format used by [Source Copy](https://github.com/exeldro/obs-source-copy)); multi-filter transfers use a versioned Unscene envelope in displayed filter order. Import checks installed filter types and compatibility, previews the names, appends without replacing existing filters, generates fresh UUIDs, and suffixes conflicting names. Pasted filters have individual OBS undo actions. Import uses the original settings and file references; external files, plugin dependencies, and source references inside third-party settings are not bundled or remapped. Share only trusted JSON: source settings may contain private paths, URLs or credentials. Full scene serialization and Source Copy scene compatibility are not yet implemented. No dependency on the Source Copy plugin.

## Portable sources
From a regular input's More actions → Portable source, copy to the system clipboard or export JSON. On a destination scene, use Portable source → Paste from clipboard or Import JSON. The single-source wrapper follows Source Copy's saved-source and transform structure, extended with the lock state. Transfers create an independent input with fresh source/filter UUIDs and a unique name, retaining native source settings, filter order, transforms, crop, visibility, locking, scaling and blending. Hotkey bindings are deliberately not cloned. Native OBS Undo removes the imported item and Redo restores its identity without activating the destination scene. Missing or incompatible types, nonduplicable inputs, groups, nested scenes and show/hide transitions are rejected rather than silently dropped. Source settings may reference external files, devices or other sources; these dependencies are not packaged or remapped. Import only trusted data. The existing reference/duplicate clipboard is unchanged.

## Quick source edits
Visibility, lock, scale filtering, blending mode/method and reset transform in Unscene's own controls register native OBS undo/redo actions. Field-level actions validate the original collection, item identity and expected field value before restoring, leaving unrelated item settings alone. The inspector retains its resized split while following other sources and when closed and reopened in the same dock session. Opening/closing uses a clipped drawer transition and tab changes use a subtle fade, governed by the same Off/Fast/Smooth motion preference. The compact header shows the source name with the full source/scene name in its tooltip, plus theme-aware icon buttons for native properties, filters, pin/unpin and close. The transform form uses short axis labels, paired numeric editors with unchanged precision and range, and hides inactive bounding-box details when Bounds is None (retaining their values). Preset load/save/delete are icon actions with tooltips; Apply and Discard remain explicit text buttons. The Filters tab uses a single compact toolbar, with rename and transfer operations under More filter actions.

## Source ordering
Drag an unlocked source row by its name or artwork above/below another source in the same scene or group. A theme-colored insertion line shows the drop position. With motion enabled, reordered rows glide into their new positions using the selected motion duration; the moved item stays in front. OBS layer changes and undo remain immediate. Large or mixed structural changes settle directly. Hold the pointer near the upper or lower edge of the source list to auto-scroll; the scroll rate increases toward the edge and the insertion marker follows the visible rows. Auto-scroll stops on release, cancellation, or when the dock is hidden. Search disables drag reordering so hidden siblings are not ambiguous. Cross-scene and cross-group drops are rejected; use the existing copy/reference actions for transfers. The expanded-row arrow buttons and Unscene Order menu also use the same native undoable reorder path. Undo/redo validates the exact sibling sequence and collection before restoring the previous order, without switching the live scene.

## Source management
Hover a scene and click the plus button, or choose Add source… from the scene’s More actions menu, to open the compact, Aftermarket-style source picker beside the dock. Add new is the initial tab; click an input type to prompt for a unique name, and configurable sources open their native properties. Add existing offers an input-type filter, name search, cached artwork or theme icons, and multiple selectable references. Make source visible controls the initial saved visibility of each added scene item. Close, Escape or outside dismissal cancels without adding. Unscene targets the chosen scene by UUID without activating it, so it uses its own creation path rather than invoking the current-scene native dialog; it does not use OBS’s native recent-source list, nested scene/group creation or native add-source undo. No additional thumbnail capture is performed.

Use a source’s More actions (ellipsis) for properties, filters, transform editing, copy, rename, appearance, and removal. Copy a source through Unscene’s More actions, then use the destination scene’s More actions to choose Paste (reference) or Paste (duplicate). Pasting preserves the copied item's transform, crop, scale filter, blending, visibility, and lock state. A duplicate creates an independent source when the source type permits it. Unscene keeps a collection-scoped clipboard and also invokes native OBS copy; native-to-Unscene clipboard import is not supported. Adding or pasting into an inactive scene does not switch the live scene. Removal targets only the selected scene item, with confirmation.

## Native OBS context menus
Right-click a scene or source in the current editing scene to open OBS’s actual context menu, including native submenus, plugin integrations and native action behavior. Unscene validates the selected scene and source item against OBS’s current model, including source instances sharing a name. The original Scenes and Sources docks may be hidden.

For inactive scenes, or if the native selection cannot be safely resolved, right-click instead opens Unscene’s expanded context menu. It offers source/scene projectors, screenshots, filters, source interaction when supported, visibility, locking, ordering, scale filtering, blending mode/method, and reset transform in addition to the existing source-management actions. These operations target the clicked item directly; no scene activation is necessary. Visibility, locking, scale filtering, blending and reset transform in Unscene use OBS Undo; add, reference/duplicate paste, removal and rename do not. The native transform editor is restricted to the current editing scene. Deinterlacing, grouping, scene removal, and additional transform presets remain native-only. An explicit Activate scene and open OBS menu action (Select preview scene in Studio Mode) is offered for inactive scenes. Right-click never silently changes the program scene. The ellipsis always opens Unscene’s own actions, independently of native selection. Native rename may require the native dock to be visible; use Unscene’s Rename action if needed. Native clipboard copying remains separate from Unscene’s cross-scene clipboard.

## Dynamic scene colors
Scene appearance colors seed a Material 3 Expressive-inspired tonal hierarchy: low-chroma source-area containers, stronger scene header containers, distinct source accent markers and contrast-checked foreground roles. Light/dark tones are derived from the active OBS palette, not fixed theme colors. Scenes set to Theme default use the active OBS Highlight color as their seed for both header and source-area surfaces, automatically following theme changes without storing a custom color; reused sources inherit their containing scene's surface while retaining their own accent. Native live/preview and selected-row highlights remain authoritative. The local OKLab gamut-mapped implementation adapts [Material dynamic color principles](https://github.com/material-foundation/material-color-utilities/blob/main/concepts/dynamic_color_scheme.md) rather than implementing Google's exact HCT Expressive scheme. No new graphics capture or runtime dependency.

Hidden sources retain their scene container color and full-strength controls, with subtly dimmed artwork and contrast-aware text. Visibility changes restore normal appearance automatically.

## Custom appearance
Open a scene or source’s More actions menu and choose Appearance. Choose automatic artwork, one of 13 built-in line icons, or import a local image/icon file. Choose a scene seed or individual source accent independently; Clear restores the theme color and Reset restores both defaults. Confirm with OK.

Appearance follows the OBS source UUID, so a reused source has consistent artwork and color across scenes. Imported artwork is stored as a bounded PNG in Unscene's own configuration, not as an external file dependency. Custom artwork takes precedence over automatic snapshots. These settings do not change the stream or the native OBS source configuration.


## Shared private notes and alternating backgrounds

Use a scene or source row's **More actions → Add note…** to attach a private note. Hover the small circled information badge to read it, or click to edit. Source notes follow the source UUID across references and renames; **Add placement note…** instead attaches to this scene item only. If both notes exist, the badge offers a choice of editor. In the inspector's Filters tab, **More filter actions → Add / edit note…** attaches to the selected filter; its icon and tooltip identify the note. Clear a note and save to remove it. Notes are plain text, limited to 4096 characters, and shared locally with Aftermarket in the sibling `aftermarket/context-notes.json` configuration file. Unscene works independently if Aftermarket is absent. File replacements are watched; saves use an atomic file replacement, a lock and expected-text conflict checks. Notes are not included in source/filter transfer exports.

**Dock settings → Alternating backgrounds → Scenes / Sources** offers Follow Aftermarket (default), On or Off independently. The shared Aftermarket `listRows` preference supplies theme-derived or custom colors and strength; Unscene applies them to its own rounded tonal surfaces, preserving explicit scene accents and selection contrast. Local On/Off overrides the enable flag only. The source stripe sequence restarts per scene branch; folder headings keep their native organization styling. Live changes are read without restarting OBS.


## Source and scene projectors

Use the Projector icon or More actions → Open source/scene projector to open an OBS-native isolated view without activating the scene. **Compact monitor window** fits the source into 320×240 logical pixels and starts near the upper right of the dock's display. **Large review window** fits within 960×640 logical pixels and centers it on that display. Both preserve the source aspect ratio when dimensions are known and shrink to fit small screens. Windowed and fullscreen display choices remain available. OBS owns rendering, source activation for display, window management and closing; its native projector context menu includes Always on Top and Resize Window to Content. These windows show the source itself, not its individual scene-item crop/transform or the entire program mix. Useful for camera framing, browser overlays, capture feeds and checking inactive scenes. Opening additional live projectors can add rendering and source activity overhead. No background capture is introduced, and no projector opens automatically.
